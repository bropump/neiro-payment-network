# Help the user run Kora with NEIRO

This is configuration and setup guidance, not an installer or a separate Kora distribution. Read docs/AGENT-SETUP.md and use upstream Kora instructions for the user's host. Do not modify Kora or its SDK.

Help the user run the whole setup in docs/AGENT-SETUP.md: install stock Kora and the portable Node.js 24+ listing runner with locked npm dependencies (no publisher compilation), configure signing and funding, derive the listing address, add it to Kora’s deny list before starting, then publish and verify direct discovery/quotes. Discover operators directly through SPL Record; do not require central router registration or a hosted verification file. Work toward a running operator rather than handing back unexplained commands. Reuse decisions and permissions already supplied; request only missing inputs. Never ask for secrets in chat.

First get it running and connected; then install the required listing renewal worker from docs/RENEWAL.md and arrange restart and upstream updates using the host's normal tools. Every operator uses anchored v5; the runner renews unchanged terms after 24 chain hours and clients reject them at 48 hours; do not retain a persistent v4 fallback. Use one worker per signer, preserve its private persistent state and stop it before closing the listing. Before replacing a Rust worker with Node, stop every old worker and verify no process remains, then reuse the same persistent state. Node runner.lock has no clock-based eviction; remove it only after verifying the old process is dead while preserving and reconciling pending.json and finalized.json. Keep signer identity and user-selected fees/allowances. Test payments only within the user's authorized spending scope. Leave a short operating guide with exact commands and clearly report what is working or incomplete.

Commit changes only as bropump.
